# Decision Log — Doctor Tracker

Approved project decisions, recorded incrementally with rationale. Fuller analysis of the
substantial ones appears in the README's Technical Decisions section at delivery.

| #  | Date       | Decision                                                                                                                               | Rationale / notes                                                                                                                            | Status   |
| -- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| 1  | 2026-10-31 | Git repository at `care_guide` root, project name `doctor-tracker`                                                                     | Directory name is cosmetic; nesting an extra folder adds no value                                                                            | Approved |
| 2  | 2026-10-31 | Monorepo via npm workspaces; no pnpm/Turbo/Nx                                                                                          | Two apps with one shared toolchain need nothing heavier; npm 11 ships workspace orchestration natively                                        | Approved |
| 3  | 2026-10-31 | MongoDB hosted on **Atlas (web)** rather than a local `mongod`                                                                          | User preference. Trade-offs: network latency, offline dev unavailable, M0 usage limits, IP allowlisting. No Atlas-proprietary features → portable | Approved |
| 4  | 2026-10-31 | Doctor **editing** included (`PATCH /api/doctors/:id` + edit form)                                                                     | Standard admin capability; small consistent extension of the doctor pattern                                                                   | Approved |
| 5  | 2026-10-31 | Patient deletion = **hard delete behind an explicit confirmation dialog**                                                              | Prevents stale sensitive data; "remove patient from a doctor's list" is exactly the delete action; all counts stay truthful                   | Approved |
| 6  | 2026-10-31 | Doctor deletion included, **rejected with `409 Conflict` while any patient is assigned**                                               | No silent orphaning of patients; no destructive cascade of unknowns                                                                           | Approved |
| 7  | 2026-10-31 | Frontend state = **Redux Toolkit; server data via RTK Query** (typed endpoints, tag-based invalidation)                                | User preference; replaces the TanStack Query option; invalidation strategy satisfies the "no stale sensitive cache" requirement               | Approved |
| 8  | 2026-10-31 | End-to-end browser tests **skipped for v1**                                                                                            | Disk (8.9 GB free) and maintenance budget; Playwright documented as future improvement; README screenshots captured without it                | Approved |
| 9  | 2026-10-31 | Testing: Vitest + Supertest (API), Testing Library (components), `mongodb-memory-server` (throwaway in-memory DB per run)               | Fully local and dodges Atlas for tests; binary download trade-off noted (~100 MB)                                                             | Approved |
| 10 | 2026-10-31 | Auth: server-side sessions in MongoDB; opaque token in `HttpOnly` cookie; only the SHA-256 hash stored; TTL index expiry; `argon2id` hashing (bcrypt fallback if native-module friction); CSRF defense via `SameSite` cookie + `Origin` validation on mutations | Real revocation; no credentials in browser storage; final design confirmed while implementing Step 5                                          | Approved |
