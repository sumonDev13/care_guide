| 10 | 2026-10-31 | Auth: server-side sessions in MongoDB; opaque token in `HttpOnly` cookie; only the SHA-256 hash stored; TTL index expiry; `argon2id` hashing (bcrypt fallback if native-module friction); CSRF defense via `SameSite` cookie + `Origin` validation on mutations | Real revocation; no credentials in browser storage; final design confirmed while implementing Step 5                                          | Approved |
| 11 | 2026-10-31 | One root `.env` at repo root for **all** workspaces (revises the earlier per-app `.env.example` proposal) | Single source of truth for dev config; both apps resolve it from the repo root; per-app files would only duplicate it | Approved |
| 12 | 2026-10-31 | Mongo access via one memoized Mongoose connection per process with explicit `dbName`; health = HTTP-200 liveness carrying explicit `database.state` + `status` ("ok"/"degraded") instead of false-503 restarts; automated tests use `mongodb-memory-server`, never the Atlas dev data | Watch-mode reload safety; truthful-but-stable monitoring signal; hermetic tests | Approved |
| 13 | 2026-10-31 | **Models:** doctor emails lowercased-on-write + unique index (case-insensitive-uniqueness without collation); patient `condition` = closed coarse enum (`general/chronic/injury/preventive/pediatric/other`) with demographics-only extras (age ≥0≤130, gender enum) → no diagnosis/test data collected; contact rule = conditional `required` functions on phone & email (cross-field validators don't run on unset paths in Mongoose); doctor-reference existence checked in a `pre("save")` hook (M0 lacks transactions — pair with Step 7's blocked-doctor-deletion rule to close orphaning both ways) | Minimal collected data (§ security posture); durable normalized uniqueness; true referential integrity without replica-set transactions | Approved |
| 14 | 2026-10-31 | **Auth:** argon2id hashing (@node-rs/argon2, OWASP m=19MiB/t=2/p=1; verified no native build friction); opaque 256-bit token in `HttpOnly SameSite=Strict` cookie, only its SHA-256 hash stored (unique index) + query-time expiry + Mongo TTL sweep; login throttle = 8/15min per IP; uniform login-failure message with dummy-hash timing equalization; CSRF = SameSite + Origin allowlist + mandatory `X-Requested-With: XMLHttpRequest` on mutations; Admin serialization never exports `passwordHash` | Real revocation; no account enumeration or timing oracles; no tokens in browser storage; CSRF triple-defense without double-submit tokens | Approved |
| 15 | 2026-10-31 | **No automated test suite** (user decision after Step 5): `apps/api/tests`, vitest, supertest and `mongodb-memory-server` removed; verification policy = `typecheck` + `lint` + `build` always green, plus guided live smoke checks against the dev database (`doctor_tracker_dev`, synthetic-only) for every feature step | User preference; frees the budget for feature steps; supersedes the tooling choice in #9 and the test clause of #12 — recorded as a documented future improvement for the README | Approved |
| 16 | 2026-10-31 | **List conventions (Step 6):** `search` = case-insensitive contains across name/email/phone/hospital (regex-escaped); `specialization`/`hospital` filters = exact match ignoring case; sort whitelist `name\|specialization\|hospital\|createdAt` with `-` prefix for descending, default `-createdAt`; `page` ≥1, `limit` 1–100 (defaults 1/10); envelope = `data` list + `meta {page,limit,total,totalPages}` (totalPages floors at 1); doctor's patient pages additionally accept a `condition` enum filter and `name\|createdAt` sorts; malformed ObjectId path params → 400, absent docs → 404 | Whitelisted, deterministic query surface that maps 1:1 to the future RTK Query params; no raw client input reaches Mongo options; grounded in the shipped indexes | Approved |
| 17 | 2026-10-31 | **Patients API + deletion rules (Step 7):** `/api/patients` — `POST` (201), `GET` (search across name/email/phone; `condition` + `doctor` filters; `name\|condition\|createdAt` sorts; decision #16 pagination), `GET /:id`, `PATCH /:id` — patch merges into current state and the FULL merged state is validated as a whole so the contact rule holds for any piecewise edit; JSON `null` clears an optional field (via `$unset`); reassignment re-verifies the new doctor exists; model `runValidators` deliberately OFF on the merged-state PATCH write (update validators can't resolve `this`-dependent cross-field rules — they read `this.phone/email` as undefined and break the contact rule on every clear); `DELETE /api/doctors/:id` → `409 CONFLICT` while any patient remains assigned else clean delete; Mongoose `ValidationError` centrally mapped to 422 as backstop | One honest delete verb per decision #5; a doctor with patients can never be silently orphaned (decision #6), patient-side pre("save") hook closes the check/delete race window; merged-state validation keeps the contact rule airtight | Approved |
| 18 | 2026-10-31 | **Frontend scaffold (Step 8):** Next.js 16 App Router workspace `apps/web` (React 19.3, exact-pinned `next`/`react`), no `src/` dir; single Redux store (`lib/store.ts`) + ONE RTK Query slice (`lib/api/api.ts`) with `Session` tags — `me` provides `Session`, login/logout invalidate it — and centrally injected `X-Requested-With: XMLHttpRequest` on every mutation via fetchBaseQuery `prepareHeaders`; API wiring = **same-origin proxy**: next.config.ts rewrites `/api/:path*` to the API origin (dev default `http://localhost:4000`; production override via the web process env `WEB_API_ORIGIN`); logout drops the ENTIRE RTK cache (listener middleware), not just a session flag; `(admin)` route-group layout guards on the live `/api/auth/me` (401 → redirect `/login`, transport failure → retry panel) since the `HttpOnly` cookie is invisible to the Next server; `/login` is public and bounces authenticated visitors via the same probe | Same-origin beats cross-origin-with-CORS for cookie auth: `SameSite=Strict` works as issued, the browser `Origin` passes the API allowlist unchanged, and no CORS exists to maintain; guarding on a live query (not a slice) keeps the session from double-source-of-truth drift | Approved |
| 19 | 2026-10-31 | **Doctors UI (Step 9):** `/doctors` = server-driven table mirroring decision #16 exactly (debounced search / specialization / hospital inputs; whitelisted sort select; 10-per-page pager), every settled filter change resets to page 1; create (`/doctors/new`) + edit (`/doctors/:id/edit`) share one form component; **API-first form validation** — forms carry no duplicate client-side rules, they render the API's 422 `details` verbatim per field and its `message` as the alert (409 duplicate email, 429 throttle land in the same alert); detail (`/doctors/:id`) shows the record card + the per-doctor patient pages with condition/sort filters (patient mutations stay for Step 10); deletion goes through an explicit confirm dialog rendering the API's 409 "patients assigned" guidance inline; tag layout: `Doctors` LIST sentinel + per-id — list provides items, create invalidates LIST, edit invalidates id+LIST, delete invalidates LIST+id; `me`-guard + logout cache-reset from Step 8 cover it all client-side | One validation truth (the API), zero rule drift; tags keep every page truthful with minimal refetch; filter state is component-local in v1 (URL sync is a documented future nicety) | Approved |
